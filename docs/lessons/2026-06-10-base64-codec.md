# Base64 코덱에서 얻은 교훈

날짜: 2026-06-10
이슈: #55

## 발생한 일

Base64 기능을 범용 바이너리/텍스트 유틸리티 모음이 아니라 범위를 좁힌 코덱
API로 추가했다. 구현은 유지 관리되는 Rust `base64` 크레이트를 사용하고
디코드 실패를 프로젝트 전용 오류 열거형으로 감싸 공개 호출자가 업스트림 오류 변형에 직접
의존하지 않도록 한다.

## 예상 밖의 문제

패딩 정책에는 명시적인 테스트가 필요하다. 업스트림 패딩 엔진은 정규 패딩
요구 사항을 사용하지만 패딩 없는 엔진은 모든 `=` 패딩을 거부한다. 필수
패딩 누락과 예상하지 못한 패딩을 모두 테스트하지 않으면 공개 함수 이름이
실제 동작보다 많은 것을 약속하게 된다.

## 다음에 할 일

- 함수 이름에 알파벳과 패딩 선택을 드러낸다.
- 표준 인코딩에 대해 엄격한 엔진과 타입이 지정된 오류를 제공하는 유지 관리
  코덱 크레이트가 있다면 이를 사용하고 Base64를 직접 구현하지 않는다.
- Base58과 Base62는 호환성과 알파벳 선택을 별도로 검토해야 하므로 자체 이슈
  (#63)에서 관리한다.
- #62가 #55보다 먼저 병합되면 어느 PR의 예제도 삭제하지 말고 코덱 README와
  Rustdoc 문구를 중심으로 주의해서 리베이스한다.
