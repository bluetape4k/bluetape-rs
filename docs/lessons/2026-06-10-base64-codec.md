# Base64 코덱에서 얻은 교훈

날짜: 2026-06-10
이슈: #55

## 발생한 일

Base64 작업은 범용 바이너리/텍스트 유틸리티 모음이 아니라 목적이 분명한
코덱 API로 구현했습니다. 구현은 유지 관리되는 Rust `base64` crate를
사용하고, decode 실패를 프로젝트가 소유하는 error enum으로 감싸 공개
호출자가 upstream error variant에 직접 의존하지 않도록 했습니다.

## 예상 밖의 발견

padding 정책에는 명시적인 테스트가 필요합니다. upstream의 padded engine은
표준 padding을 요구하지만 no-padding engine은 모든 `=` padding을 거부합니다.
필수 padding 누락과 예기치 않은 padding을 각각 테스트하지 않으면 공개 함수
이름이 실제 동작보다 과도한 약속을 하게 됩니다.

## 다음에 적용할 규칙

- 함수 이름에 알파벳과 padding 선택을 드러냅니다.
- strict engine과 typed error를 제공하는 유지 관리 코덱 crate가 있다면 표준 인코딩에 사용하고 Base64를 직접 구현하지 않습니다.
- Base58과 Base62는 호환성과 알파벳 선택을 별도로 검토해야 하므로 자체 이슈(#63)로 유지합니다.
- #62가 #55보다 먼저 merge되면 codec README와 Rustdoc 문구 주변을 주의해서 rebase하고 어느 PR의 예시도 삭제하지 않습니다.
