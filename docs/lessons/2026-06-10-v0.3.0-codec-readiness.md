# v0.3.0 코덱 릴리스 준비 상태에서 얻은 교훈

날짜: 2026-06-10

## 교훈

릴리스 준비 작업에서는 준비 상태 근거와 릴리스 실행을 분리해야 한다.
`0.3.0`에서는 하위 이슈를 검증하고 패키지 드라이런을 통과할 수 있지만,
`develop`을 `main`으로 승격하고 `main`에서 태그를 만들고 GitHub Release를
게시하기 전까지는 안정 릴리스가 완료되지 않는다.

## 적용 규칙

- 준비 상태를 말하기 전에 마일스톤의 모든 하위 이슈를 확인한다.
- `main`과 `develop`의 정확한 커밋을 기록한다. `main`은 안정 릴리스
  브랜치이고 `develop`은 개발 브랜치다.
- `cargo publish --dry-run`은 패키징 근거로만 사용하고 준비 상태 PR에서
  게시하지 않는다.
- 보류한 마일스톤 경계를 명시적으로 유지한다. 압축은 `0.4.0`에,
  직렬화는 `0.5.0`에 남긴다.
