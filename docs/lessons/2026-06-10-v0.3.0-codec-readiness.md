# v0.3.0 코덱 릴리스 준비에서 얻은 교훈

날짜: 2026-06-10

## 교훈

릴리스 준비 작업에서는 readiness 근거와 실제 릴리스 실행을 분리해야
합니다. `0.3.0`에서는 하위 이슈를 검증하고 package dry-run을 통과시켜도,
`develop`을 `main`으로 promote하고 `main`에서 tag를 생성한 뒤 GitHub
Release를 publish하기 전까지 stable release는 완료되지 않습니다.

## 적용한 규칙

- readiness를 주장하기 전에 모든 milestone 하위 이슈를 확인합니다.
- 정확한 `main` 및 `develop` commit을 기록합니다. `main`은 stable release branch이고 `develop`은 development branch입니다.
- `cargo publish --dry-run`은 packaging 근거로만 사용하고 readiness PR에서 publish하지 않습니다.
- 보류된 milestone 경계를 명시적으로 유지합니다. compression은 `0.4.0`, serialization은 `0.5.0`에 남깁니다.
